# Issue #202：中文标点粗体兼容

由 dot 按用户于 2026-10-23 的明确要求整理和实现；日期按北京时间。Refs #202。

## 问题与范围

最小文本来自报告者 2026-10-23 的评论：`**律师：**后果很严重。`。结束双星前是标点、后是文字，不满足 CommonMark 的右侧闭合边界。真实 Lute 和 GitHub 评论渲染均保留字面双星。PR #206 处理已存在 strong 节点的点击展开，不能替代本修复；PR #203 处理另一个启动恢复诉求。

本次只扩展同一普通文本 token 内、含汉字、以字母/数字起始且以标点结尾、双星后紧接字母/数字的粗体。典型句首标签和正文、标题、列表、引用、表格一致生效。不给普通英文星号重新配对，不跨代码/转义/实体/链接/HTML/嵌套格式节点寻找结束标记；脚注保留原行为。用户原文不增加空格、反斜杠、HTML 或不可见字符。

已知限制：`**律师：**后果**警告：**立即处理。` 这类同段多组标记，Lute 可能已把中间正文配成 strong，本补丁不重新解释已有节点，仍按原生显示（源码不丢失）。Vditor 粘贴会去掉开头空行并解包单一段落，若要粘成独立段落，应先 Enter 再粘贴；回归同时保留该交叉配对负面用例，不声称通用 CJK 强调解析。

## 实现与数据边界

- 用原生 IR strong 与 marker 节点呈现；调用原生 Lute 序列化，保持源双星和冒号原位置。
- 包装每个编辑器实例的 IR 生成/Spin/HTML 导入返回值，不改全局 Lute，不修改 vendor。仅初始确有兼容片段时重建同一 source 的撤销基线，不发出源码变更。
- HTML/Word 纸张预览、HTML 导出共用官方 renderText hook，沿用 sanitize 链及原 autoSpace/fixTermTypo=false。DOCX 独立解析器本来支持目标样例，补断言而不修改其语义。
- HTML 解析使用 inert template；代码块/行内代码、转义星号、实体星号、链接、原始 HTML、脚注及嵌套格式不扩展。
- 仍有 Vditor 原有的 LF 与末尾换行规范化；要求是本兼容层不额外改写内容，而非声称整个既有编辑器逐字节保留所有 Markdown。
- 公开 Protyle 开关经过反例验证后舍弃：它不只是 CJK 开关，`<br>` 往返出现错误文本，不能用于安全修复。
